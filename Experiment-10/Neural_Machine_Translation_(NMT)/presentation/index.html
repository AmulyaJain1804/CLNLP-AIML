01 · Introduction

Translating languages that barely have data

Neural MT works well when there are millions of sentence pairs. North-East India has dozens of languages with only a few thousand. The WMT26 Indic MT shared task releases parallel data for 11 of them. We asked how far careful engineering can take a model in this regime.

The problem

English ↔ Assamese, Manipuri, Mizo, Bodo, with 11k–49k training pairs each. That is 100–1000× less than high-resource pairs.

Why it is hard

Four scripts (Bengali-Assamese, Bengali, Latin, Devanagari), rich morphology, noisy web/religious-domain data, and one language (Bodo) that no large pretrained MT model has seen.

Our goal

Compare a Transformer baseline with two improvements: back-translation and transfer learning from NLLB-200. Evaluation uses confidence intervals and significance tests.

WMT26 Indic MT, 2026 release

Cleaning (train only): NFC normalisation, removal of empty, duplicate and wrong-script pairs and length-ratio filtering, plus removal of every pair that overlaps dev/test. Dev and test are never filtered. Tokeniser: a joint SentencePiece unigram model per pair (8k vocab; 6k for Bodo).

Protocol

  • A fixed dev set for checkpoint selection and early stopping. The test set is decoded once.
  • Train ∩ test overlap is removed; the tokeniser sees train only.
  • Seed 42 everywhere. Every run logs its config, hardware and wall-clock time.

Runs

05 · Results · error analysis

Where the models fail

Error categories (64 worst sentences per model)

≈⅓ are not model errors

Many of the "worst" test pairs are misaligned in the release. One example is a long sentence whose reference is just a Bible verse number. NLLB often translates these correctly and still scores about 5 chrF++.

Omission dominates

The scratch models stop early on long or rare-word inputs. NLLB omits less (31 against 36–37 of 64).

Loops and names

Hallucinations are repetition loops on lists of names. Back-translation adds named-entity errors, because its synthetic data garbles names.

06 · Conclusion & future scope

Key takeaways

1

Pretrained multilingual transfer dominates. NLLB-200 beats the baseline by 4–19 chrF++ in every direction, and learns unseen Bodo through a proxy tag.

2

Back-translation needs a good generator. With noisy synthetic data (round-trip chrF++ 20–27), it helps only the smallest pair. This is an honest negative result.

3

Evaluation hygiene matters. About a third of the worst test cases are misaligned references, so CIs and error analysis change how the results should be read.

Future scope

  • Back-translation with NLLB as the generator, sampling, and tuned synthetic ratios
  • One multilingual model for all 11 pairs, with related-language transfer (as → mni)
  • LoRA / larger NLLB (1.3B, 3.3B) within the same GPU budget
  • Decoding fixes: repetition penalty, n-gram blocking
  • Evaluation on the official test set, with COMET and human judgements

Limitations: our own held-out split (not leaderboard-comparable), a single seed, noisy references, and possible overlap between NLLB's pre-training data and public Bible/news text.
